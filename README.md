# Satisfactory服务器搭建：先算清内存和单核性能，再照着步骤把工厂挂上 VPS

存档建到第三座工厂的时候，通常就是联机体验开始崩的时候。主机那个人下班、出差、睡觉，剩下的人就只能干等——Satisfactory 的联机默认是「客户端开房间」，世界绑在某个人的电脑上。专用服务器（Dedicated Server）解决的正是这件事：它不渲染画面、不需要显卡，只把工厂模拟和存档跑在一台 7×24 在线的机器上，谁在线都不影响流水线继续转。

下面按真正会卡住人的顺序讲：要多少内存、开哪些端口、怎么装服务端、机器怎么挑，以及在这个场景里雨云哪几档机型值得看。

## 先算账：这台服务器到底吃什么资源

网上流传的配置建议差距很大，原因是很多帖子把「能开起来」和「晚期存档能跑」混在一起说。官方文档的口径是**最低 8GB 内存，大存档或 4 人以上建议 16GB**[1]，Docker 镜像维护者的说明也基本一致——8GB 到 16GB，晚期存档或人多要往上加[2]。

按工厂阶段拆开看更实用：

| 阶段 | 内存 | CPU | 说明 |
| --- | --- | --- | --- |
| 开局 1–2 人 | 4–6GB | 2 核 | 机器少，传送带短 |
| 中期（MK2–MK4 传送带、火车） | 8–10GB | 3–4 核 | 多条产线同时运行 |
| 晚期（核电、火车网） | 12–16GB | 4 核 | 数千台机器 |
| 巨型基地 | 16GB 以上 | 4 核以上 | 存档动辄几百 MB |

这些数字来自多个主机商的公开技术文档[3][4]，彼此差异不大，可以放心当作选型基线。

硬盘别省。服务端本体加游戏文件大概 15GB，装完加存档，30GB 起步比较稳；Satisfactory 存档在后期会膨胀到几百 MB，用机械盘会在自动保存时出现明显卡顿，NVMe 是更实际的选择[3][4]。

还有一条容易被忽略：**Satisfactory 服务端重度依赖单核性能**。它的核心循环本质上是串行 tick，核心数翻倍收益很小，主频拉高收益很大[3]。如果你在「更多核」和「更快核」之间犹豫，这个游戏永远选后者。

## 端口、认领和「退出前先 quit」：三个最容易踩的坑

先说端口，这是从 Minecraft 转过来的人最容易翻车的地方：

- **7777 TCP**：服务器通信和 HTTPS API
- **7777 UDP**：游戏流量和轻量查询
- **8888 TCP**：可靠消息通道
- 15000 UDP（beacon）和 15777 UDP（查询）在不少教程里也会一并打开[4][5]

关键限制是：**标准端口不支持端口重定向，外网端口号必须和内网一致**。你不能把 7777 映射成别的号还指望连上，7777 就得是 7777。8888 是唯一相对灵活的，可以用 `-ExternalReliablePort=` 改[3]。

第二个坑是「认领」。光把 IP 粘进连接框是进不去的，Satisfactory 走的是客户端自带的服务器管理界面：打开游戏 → Server Manager → 添加服务器 → 填 IP 和 7777 → 起个名字 → 设管理员密码。**只有走到设置管理员密码这一步，认领握手才算完成**，未认领的服务器会直接拒绝连接[3]。密码请当场设强一点，别拖到第二天。

第三个坑出在关服上。服务端 5.0.4 之后的版本，控制台是唯一能执行命令的地方，要停服得在控制台里敲 `quit`，让它把存档写完再退出。直接杀进程的做法可能导致这次进度没保存[5]。

另外两个默认值值得知道：服务端默认上限 4 人，可以用启动参数 `-ini:Game:[/Script/Engine.GameSession]:MaxPlayers=8` 拉到 8 人，但这个做法官方并不支持[3]；服务器设置里还有「无人时暂停」和自动保存间隔，前者能显著省下闲置时的 CPU 开销。

## 在 VPS 上装服务端：SteamCMD 和 Docker 两条路

服务端本身免费，在 Epic 和 Steam 都能拿到。Linux 上最直接的是 SteamCMD：

bash
# 安装（App ID 1690800）
steamcmd +force_install_dir /home/satisfactory +login anonymous +app_update 1690800 validate +quit

# 启动
cd /home/satisfactory
./FactoryServer.sh -log -unattended


几条实操经验：整个下载过程要拉 8–15GB 文件，第一次装建议留出十几分钟；用 `anonymous` 匿名登录就够；Ubuntu 22.04 以上是最省心的系统版本，Windows Server 也支持，但 Linux 更省资源；数据目录在 `~/.config/Epic/FactoryGame/Saved/SaveGames/server/`，顺手挂个定时打包脚本，比出事以后找存档靠谱。

不爱折腾命令行的话，社区有现成的 Docker 镜像 `wolveix/satisfactory-server`，配置项写得很清楚：`MAXPLAYERS` 默认 4、`MAXTICKRATE` 默认 30、`MAXOBJECTS` 默认 2162688（大工厂需要调高），容器启动时会自动更新游戏[2][6]。代价是首次启动要等 5–10 分钟下载文件，而且内存限制得手动设成 12G 或 16G[6]。

## 为什么开这个服，单核性能比核心数更值钱

把上面那些要求落到租机器上，结论其实很窄：**高主频 + 8GB 以上内存 + NVMe + 能开 UDP 端口**。

普通云服务器通常给的是 Xeon Platinum / Gold 这类多核吞吐型 CPU。第三方实测里，湖北十堰 Xeon Platinum 8272CL 机型的 Geekbench 6 单核跑分在 1200 分上下[7]；而同一家厂商的高主频游戏云机型，i9-14900KF 的 Geekbench 6 单核能到 2798 分，宁波 i9-14900K 机型是 2836 分[8][9]。这类机器还有个细节：14900KF 和 13900KF 机型屏蔽了小核、只跑纯大核，超频到 6.3GHz，属于专门为「吃单核」的业务准备的[10]。对 Satisfactory 晚期那种几千台机器同时 tick 的存档来说，这个差距会直接体现在延迟和卡顿上——**同样 4 核 8G，跑分差一倍，体验就不是一个档位**。

所以如果你打算用它开 Satisfactory 服，优先级是：高主频游戏云 ≥ 高频云服务器 > 通用云服务器。

## 几个常见问题

**能装在 Windows 上吗？** 可以，官方也支持 Windows Server，但 Linux（Ubuntu 22.04/24.04）占用更低、更新更方便，雨云云服务器两种系统都能装。

**服务器需要显卡吗？** 不需要。专用服务端不做渲染，纯 CPU + 内存负载。

**4 核 8G 能撑到什么时候？** 开局到中期没问题。如果你们打算长期玩下去、基地规模往核电和火车网发展，建议直接上 16GB，或者留好后续升级内存的余地——雨云支持弹性变配和扩容云盘[11]。

**NAT 机型能开这个服吗？** 能。Satisfactory 只需要 7777 TCP/UDP、8888 TCP 这几个端口，NAT 的端口映射条数够用，注意外网端口号和内网保持一致。代价是只适合做游戏服，不适合拿来建站。

**服务器被攻击怎么办？** 这是公开游戏服的常见问题，选带高防的机型（比如镇江 200G、十堰 200–600G）比事后加防护省心。

最后一句实在话：Satisfactory 开服真正的门槛不在命令，而在选机器。先把内存和单核性能这两件事算对，剩下的步骤照着上面的端口和认领流程走，半小时内就能进厂。
